# Contrato del Workshop 2 — Streams de solicitudes y resumenes en linea

Este archivo es todo lo que hace falta para entregar una task del Workshop 2
y que aparezca en el dashboard. Se puede pegar completo en una IA: no hace
falta mostrarle el resto del repo.

## Como se entrega una task

1. **Un solo archivo de Python:** `src/w2/taskK_tema.py`, donde K es el numero
   de la task y `tema` una palabra en minusculas (p. ej. `src/w2/task2_bloom.py`).
   No hay que registrarlo en ninguna lista: el dashboard, `run_all.py` y la app
   web lo encuentran por el nombre.
2. **Solo biblioteca estandar** (`csv`, `json`, `math`, `random`, `hashlib`,
   ...). Nada de `pip install`: el mismo archivo corre tambien en el navegador.
3. **Empieza con este bloque**, tal cual, antes de los demas imports:

   ```python
   import os

   BASE = os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
   DATA_DIR = os.path.join(BASE, "data")
   RESULTS_DIR = os.path.join(BASE, "results", "w2")
   os.makedirs(DATA_DIR, exist_ok=True)
   os.makedirs(RESULTS_DIR, exist_ok=True)
   STREAM_CSV = os.path.join(DATA_DIR, "stream.csv")
   ```

4. **Todo lo que hace va dentro de `if __name__ == "__main__":`**; arriba del
   archivo solo constantes y funciones.
5. **Es un stream:** se lee `stream.csv` fila por fila en orden de
   `stream_seq`, y lo que se guarda en memoria es el resumen (el filtro, el
   reservorio, los contadores), no las filas. Para comparar contra el valor
   verdadero si se puede llevar un conteo exacto aparte.
6. **Reproducible:** si usa azar, semilla fija (`random.Random(42)`). Para
   hashear, `hashlib` (p. ej. `blake2b` con distinta `salt` o `key` por
   funcion); nunca `hash()` de Python, que cambia en cada corrida.
7. **Escribe `results/w2/taskK.json`** con al menos las claves del ejemplo de
   su seccion (abajo). Puede tener mas; el dashboard ignora las que no estan:

   ```python
   with open(os.path.join(RESULTS_DIR, "task2.json"), "w", encoding="utf-8") as f:
       json.dump(resultado, f, indent=2, ensure_ascii=False)
   ```

8. **Revisar antes de subir:**

   ```bash
   python run_all.py w2                   # genera rides.csv y stream.csv, y corre lo que haya
   python src/w2/task2_bloom.py           # o solo la task
   python dashboard/contrato.py w2 2      # dice OK o que clave falta
   ```

   Si dice OK, el JSON tiene el formato que lee el panel (claves y tipos; no
   revisa que los numeros esten bien). Para verlo: `cd web && npm install && npm run dev`.

### Como leer los ejemplos

- `"clave": 1.5` es un numero (entero o decimal da igual); `"clave": "texto"`,
  un texto; `true`, un booleano; `null`, cualquier cosa.
- `"clave?"` (con signo de interrogacion) es **opcional**: si la task la
  escribe, se revisa y el panel la usa; si no, no pasa nada. En el JSON va sin
  el signo.
- En una lista, **cada** elemento debe tener la forma del primero del ejemplo.
- `{"*": 3}` es un diccionario con claves libres (p. ej. una por zona).
- Ningun numero puede ser `NaN` ni infinito: el navegador no los lee.
- Las listas largas (una entrada por evento) hacen pesado el dashboard: para
  las series en el tiempo basta un punto por hora del stream (~336 puntos).

### La pagina de la task (opcional)

Cada task puede tener una pagina con su explicacion, que tambien sirve de
diapositiva. Es un archivo aparte, `web/lib/docs/w2/taskK.ts`; no hay que
tocar ningun otro archivo de la app:

```ts
import type { TaskDoc } from "@/lib/tasks";
import type { W2Task2 } from "@/lib/generated/contratos";
import { fmt, int, pct } from "@/lib/format";

const doc: TaskDoc<W2Task2> = {
  title: "Titular corto y afirmativo",
  topic: "FILTRO DE BLOOM",
  statement: "El enunciado, en espanol.",
  standfirst: "Resumen sin cifras (se muestra antes de que haya datos).",
  // r es el JSON de la task, con las claves de su ejemplo.
  lede: (r) => `Con n = ${int(r.n_bits)} bits y k = ${int(r.k)} ...`,
  metrics: (r) => [{ label: "FP empirico", value: pct(r.fp_empirical, 2), hint: "de donde sale" }],
  sections: [{ h: "Paso 1", p: "Explicacion." }],
  takeaway: "La frase de cierre.",
};
export default doc;
```

`W2Task2` (y los demas) se generan solos a partir de los ejemplos de este
archivo: el editor autocompleta las claves.

## Los datos

`src/w2/dataset.py` lee `data/rides.csv` (el del Workshop 1, sin tocarlo) y
escribe `data/stream.csv`: las mismas filas en orden de llegada, con dos
columnas nuevas. ~495.000 eventos, 14 dias, 10 zonas.

| columna | tipo | ejemplo |
|---|---|---|
| ride_id | texto | `b3cfd7280b5c` |
| timestamp | texto ISO | `2026-09-01T00:00:03` |
| rider_id | texto | `rdr_14534` |
| driver_id | texto | `drv_00150` |
| pickup_zone | texto | `AIRPORT` |
| distance_km | decimal | `3.87` |
| fare | decimal | `9649.0` |
| stream_seq | entero | `1` (1, 2, 3, ... en orden de llegada) |
| wait_for_driver_sec | decimal | `74.0` |

`wait_for_driver_sec` sube cuando hay muchas solicitudes a la vez en la misma
zona (misma ventana de 5 minutos): la espera media va de ~40 s con la zona
vacia, de madrugada, a ~190 s en las ventanas mas concurridas.

## Task 1 — Modelo de stream y diseno de consultas

Consulta permanente: promedio movil de `wait_for_driver_sec` por zona sobre
las ultimas 500 solicitudes. Consulta ad hoc: cuantos pasajeros distintos
pidieron viaje en la ultima hora. Estimar el tamano del almacen de trabajo
dentro de un presupuesto de 10 MB.

- `n_events`: eventos leidos del stream.
- `window_n`: tamano de la ventana de la consulta permanente (500).
- `window_scope`: como se lee "las ultimas 500 solicitudes", que el enunciado deja abierto: `"por zona"` (las ultimas 500 de cada zona) o `"ciudad"` (las ultimas 500 de toda la ciudad, agrupadas por zona).
- `checkpoints`: fotos del estado de las dos consultas a lo largo del stream (p. ej. una al final de cada hora).
  - `timestamp`: el del ultimo evento antes de la foto.
  - `rolling_avg_wait`: promedio movil en segundos, uno por zona: `{"AIRPORT": 61.2, "DOWNTOWN": 48.7, ...}`.
  - `distinct_riders_last_hour`: respuesta de la consulta ad hoc en ese momento.
- `budget`: el almacen de trabajo.
  - `limit_bytes`: el presupuesto (10 MB = 10485760).
  - `items`: cada estructura que se guarda y cuantos bytes ocupa.
  - `total_bytes`: la suma.

```json
{
  "n_events": 495505,
  "window_n": 500,
  "window_scope": "por zona",
  "checkpoints": [
    {
      "timestamp": "2026-09-01T00:59:58",
      "rolling_avg_wait": { "*": 61.2 },
      "distinct_riders_last_hour": 812
    }
  ],
  "budget": {
    "limit_bytes": 10485760,
    "items": [
      { "name": "ventana de 500 esperas por zona", "bytes": 40000 },
      { "name": "pasajeros de la ultima hora", "bytes": 52000 }
    ],
    "total_bytes": 92000
  }
}
```

## Task 2 — Filtro de Bloom

Filtro de Bloom de los pasajeros ya emparejados en el minuto en curso, para
no despacharlos dos veces. Elegir k = floor((n/m) ln 2) y medir la tasa de
falsos positivos empirica contra la teorica.

Notacion del curso: **n = bits del filtro, m = elementos insertados.**

- `n_bits`, `m_items`, `k`: el diseno del filtro.
- `fp_theoretical`: (1 - e^(-k m / n))^k.
- `fp_empirical`: falsos positivos / consultas de pasajeros que NO estaban en el filtro.
- `running`: la tasa empirica acumulada a lo largo del stream ("lo que va del stream"), p. ej. un punto por hora.

```json
{
  "n_bits": 4096,
  "m_items": 300,
  "k": 9,
  "fp_theoretical": 0.0014,
  "fp_empirical": 0.0011,
  "running": [
    { "timestamp": "2026-09-01T00:59:58", "fp_rate_so_far": 0.0009 }
  ]
}
```

## Task 3 — Muestreo sobre el stream

Reservoir sampling para estimar la tarifa y la espera promedio por zona;
comparar con los valores verdaderos con reservorios de 100, 300 y 500.

- `sizes`: los tamanos de reservorio.
- `zones`: una fila por zona.
  - `true_avg_fare`, `true_avg_wait`: el promedio verdadero (conteo exacto aparte).
  - `by_size`: lo que estima el reservorio de cada tamano.

```json
{
  "sizes": [100, 300, 500],
  "zones": [
    {
      "zone": "AIRPORT",
      "true_avg_fare": 10220.3,
      "true_avg_wait": 79.6,
      "by_size": [
        { "size": 100, "est_avg_fare": 10180.0, "est_avg_wait": 81.2 }
      ]
    }
  ]
}
```

## Task 4 — Conteo de distintos

Flajolet-Martin para estimar cuantos `rider_id` distintos hay en el stream,
con 10 o mas funciones hash, contra el conteo verdadero.

- `n_hashes`: cuantas funciones hash.
- `true_distinct`, `estimate`: el conteo exacto y el de Flajolet-Martin al final del stream.
- `combine` (opcional): como se combinan las estimaciones (p. ej. `"mediana"`).
- `per_hash` (opcional): la estimacion 2^R de cada funcion hash.
- `running` (opcional): los dos valores a lo largo del stream, p. ej. un punto por hora. Si viene, el panel dibuja la serie; si no, muestra solo los valores finales.

```json
{
  "n_hashes": 10,
  "true_distinct": 19998,
  "estimate": 16384,
  "combine?": "mediana",
  "per_hash?": [16384, 32768],
  "running?": [
    { "timestamp": "2026-09-01T00:59:58", "true_distinct": 820, "estimate": 1024 }
  ]
}
```

## Task 5 — Momentos de frecuencia

F0, F1 y F2 exactos sobre `pickup_zone`. Un F2 alto significa que pocas zonas
concentran la demanda: candidatas a surge.

- `counts`: f_i, cuantas veces aparece cada zona: `{"AIRPORT": 69900, "DOWNTOWN": 64800, ...}`.
- `F0`, `F1`, `F2`: zonas distintas, largo del stream, suma de f_i^2.

```json
{
  "F0": 10,
  "F1": 495505,
  "F2": 26291500000,
  "counts": { "*": 69900 }
}
```
